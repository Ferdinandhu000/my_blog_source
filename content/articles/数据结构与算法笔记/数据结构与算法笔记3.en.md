## Trident Search Tree (BST)
The left value of any node is less than that node and the right node is greater than that node
### To judge whether a tree is.`BST`
#### Thinking.
If the left node is not empty and the maximum value of the left node is greater than that point, it is certainly not`BST`, same logic judge the right node, if both the right and the left node match, then the right and the left node are to be subordinated
#### Code
```java
public static boolean isBST(Node n) {
    if(n == null) return true;
    if(n.left != null && treeMax(n.left).key > n.key) return false;
    else if(n.right != null && treeMin(n.right).key < n.key) return false;
    else return isBST(n.left) && isBST(n.right);
}

// Using recursion to implement treeMax
public static Node treeMax(Node n) {
    if(n.right != null) return treeMax(n.right);
    else return n;
}
// Using iteration to implement treeMin
public static Node treeMin(Node n) {
    while(n.left != null) {
        n = n.left;
    }
    return n;
}
```

Here.`treeMax`and`treeMin`The solution is to assume that the tree is already`BST`I'm looking for it under conditions.`right`or`left`At the end, it's kind of like a necessity test.`BST`

### Insert Operations`insert`)

public static void insert(Node root, Node n) {
    Node y = null; // y 用来临时存放上一步的节点
    Node x = root;
    while(x != null) {
        y = x;
        if(n.key < x.key) {
            x = x.left;
        }
        else {
            x = x.right;
        }
    }

    if(y == null) root = n;
    else if(n.key < y.key) y.left = n;
    else y.right = n;
}

### Forward and follow-up`predecessor` & `successor`)
Forward: the first node below this node
Subsequent: the first node with greater value than this node
#### Thinking.
If you are looking for a front or a follow-up, the node is to be predefined by depositing the corresponding parent node(s).`node.p`)。  
If you're looking for a front.`predecessor`) First, if there is a left node, return the maximum value directly to the left node (`treeMax()`I don't know. If the node does not have a left node, the parent node will need to be sought continuously. If it is not the right node of its first parent node (which means that it is smaller than its first father node), the cycle continues to be looked up. And so will the search.
#### Code
```java
public static Node successor(Node x) {
    if(x.right != null) return treeMin(x.right);
    Node y = x.p;
    while(y != null && x == y.right) {
        x = y;
        y = y.p;
    }
    return y;
}
public static Node predecessor(Node x) {
    if(x.left != null) return treeMax(x.left);
    Node y = x.p;
    while(y != null && x == y.left) {
        x = y;
        y = y.p;
    }
    return y;
}
```

## Broad Search Priority (BFS)
![](https://raw.githubusercontent.com/Ferdinandhu000/my_blog_img/master/20251214155916.png)
### Thinking.
In the chart search, each point is no longer a node (`Node`), it's the top point.`Vertex`I don't know. Every one.`Vertex`contains the following properties:
- `name`: Node Name
- `pi`：`parent`Parent node (previous position)
- `d`Distance from initial position
- `color`Status tag (white-unsearched, ash-to-search, black-searched)
Yes.`BFS`, use a queue to maintain pending search`vertex`(grey) Initialization sets the initial position to grey and inserts it in the queue, setting the remaining points to white. Each time the first element of the team pops up, changes the state (grey-> black) and inserts in the queue the elements (and white) that are connected around it, changes the colour and`pi`

### Code
```java
// Vertex 类
class Vertex implements Comparable<Vertex> {
    Color color;
    Vertex pi;
    String name;
    int d;

    public Vertex(String name) {
        this.name = name;
        this.color = Color.WHITE;
        this.pi = null;
        this.d = 0;
    }

    // 要接入Comparable接口并重写compareTo方法，否则存入G时会与TreeMap冲突
    @Override
    public int compareTo(Vertex o) {
        return this.name.compareTo(o.name);
    }
    @Override
    public String toString() {
        return name;
    }
}
```

```java
// BFS
public static void BFS(Map<Vertex, ArrayList<Vertex>> G, Vertex s) {
    s.color = Color.GRAY;
    Queue q = new LinkedList<>();
    q.add(s);
    while(!q.isEmpty()) {
        Vertex u = (Vertex) q.poll();
        for(Vertex v : G.get(u)) { // 与u相邻的元素
            if(v.color == Color.WHITE) {
                v.color = Color.GRAY;
                v.d = u.d + 1;
                v.pi = u;
                q.add(v);
            }
        }
        u.color = Color.BLACK;
    }
}
```
Query from the beginning at this time`s`To a certain position`v`Shortest path, return`v.d`Yeah.

## Minimal Generating Tree (MST)
![](https://raw.githubusercontent.com/Ferdinandhu000/my_blog_img/master/20251217154448.png)

### Thinking.
Core thinking:**Greedy strategy**
First all elements are placed in a priority queue to facilitate follow-up`poll`Manage and maintain queues. will start with`d`Set as`0`The rest is infinity. Every time`poll`Queue Header Elements`u`And across the adjacent elements.`v`change if the value of the point is less than the current value`v.pi`and`v.d`  
In Java, a `PriorityQueue` does not update its ordering when an element changes. Remove the element, update it, then add it to the queue again.

### Code
```java
public static void prim(Map<Vertex, Map<Vertex, Integer>> G, Vertex r) {
    r.d = 0;
    PriorityQueue<Vertex> Q = new PriorityQueue<>((v1, v2) -> v1.d -v2.d); // Lambda表达式
    for(Vertex v : G.keySet()) {
        Q.add(v);
    }
    while(!Q.isEmpty()) {
        Vertex u = Q.poll();
        for(Map.Entry<Vertex, Integer> v : G.get(u).entrySet()) { // 留意这里的写法，是entrySet()
            if(Q.contains(v.getKey()) && v.getValue() < v.getKey().d) {
                Q.remove(v.getKey()); // 先删除
                v.getKey().pi = u; // 在外部修改
                v.getKey().d = v.getValue();
                Q.add(v.getKey()); // 最后添加回去
            }
        }
    }
}

```
